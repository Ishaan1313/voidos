sounddevice>=0.4.6

# The Intercom on Linux prefers host command-line tools to pip packages. They
# need to be on PATH, and the Intercom page's set-up check says exactly which
# is missing:
#   - bluetoothctl (BlueZ)         — sudo apt install bluez
#   - pw-record / pw-play / pw-dump (PipeWire) — sudo apt install pipewire pipewire-audio wireplumber
# Raspberry Pi OS Bookworm and earlier default to the older PulseAudio stack, so
# install PipeWire explicitly (or use the PortAudio fallback above).

# Continuous Cloud Sync (see README's Cloud Storage section) also shells
# out to a host CLI tool rather than a pip package — the same pattern as
# Bluetooth/PipeWire above:
#   - rclone — curl https://rclone.org/install.sh | sudo bash (or your package manager)
# Settings → Cloud Storage detects and reports if it's missing, same as
# the Intercom tab does for bluez/pipewire. Browsing/importing/exporting
# single files (the non-continuous cloud storage path) doesn't need this
# at all — only enabling a continuous sync pair does.

# External Storage (see README's External Storage section) also shells
# out to host tools, no pip packages:
#   - udisksctl (udisks2)              — USB mount/unmount, no root needed
#   - lsblk (util-linux)               — USB device discovery
#   - mount.cifs (cifs-utils)          — SMB network shares
#   - mount.nfs (nfs-common)           — NFS network shares
# Settings/Access Control → External Storage detects and reports exactly
# which of these is missing, same as the Intercom tab does for bluez/
# pipewire. SMB/NFS additionally need root or passwordless sudo for
# mount/umount — reported clearly with the exact sudoers line to add if not.

# Notices changes in the synced Dropbox folder the moment they happen (instant two-way sync).
